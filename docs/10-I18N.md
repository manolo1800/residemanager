# 10 — Internacionalización (i18n)

---

## 🌎 Idiomas soportados

| Código | Idioma | Región principal |
|---|---|---|
| `es` | Español | América Latina, España |
| `en` | Inglés | Global |
| `fr` | Francés | Caribe, Canadá, África |
| `pt` | Portugués | Brasil, Portugal |

**Regla:** toda clave nueva se agrega en **los 4 idiomas** simultáneamente. Si falta traducción, se usa fallback `en`.

---

## 🎯 Resolución del idioma

Orden de prioridad:

1. Preferencia explícita del usuario (`users.locale`).
2. Preferencia del tenant (`tenants.primary_locale`).
3. Default del sistema (`es`).

El idioma **no** cambia por condominio. Es del usuario o del tenant.

## 🔑 Convención de claves

Formato: `<namespace>.<section>.<key>`

Ejemplos:
common.buttons.save
common.buttons.cancel
common.errors.network
payments.title
payments.status.approved
payments.status.approved_pending_data
payments.errors.duplicate_reference
billing.fees.ordinary
billing.fees.extraordinary


**Reglas:**
- `camelCase` en las claves.
- Nunca usar el texto como clave.
- Nunca anidar más de 3 niveles.
- Nunca concatenar strings traducibles en código.

## 🖥️ Backend

Librería: **nestjs-i18n**.

Uso:
```ts
throw new DomainException(
  'PAYMENT_NOT_FOUND',
  this.i18n.t('payments.errors.not_found', { args: { id } }),
  404
);
Los mensajes se generan en el idioma del usuario destinatario.

🎨 Frontend
Librería: next-intl.

Uso:

import { useTranslations } from 'next-intl';

const t = useTranslations('payments');
return <h1>{t('title')}</h1>;

app/[locale]/...

Middleware detecta locale desde cookie o header, con fallback al default.

📅 Zonas horarias
Almacenamiento
Todas las fechas en UTC en la base de datos.

Columnas timestamptz.

Resolución
Timezone del condominio (condominiums.timezone).

Timezone del usuario (users.timezone).

Default por país del condominio.

Render
Frontend usa Intl.DateTimeFormat con timezone del condominio.

PDFs (recibos, actas) usan timezone del condominio.

Emails y notificaciones usan timezone del destinatario.

Cambio de timezone
El admin puede cambiar la timezone del condominio desde configuración.
Los usuarios pueden ajustar la suya en su perfil.

🕐 Formato de hora
Interno: siempre 24h.

Visualización: configurable por condominio (condominiums.date_format).

Ejemplos:

24h: 14:30

12h: 2:30 PM

Regla: aunque el usuario elija 12h para visualización, el almacenamiento interno sigue siendo 24h UTC.

📆 Formato de fecha
Configurable por condominio:

Formato	Ejemplo
DD/MM/YYYY	12/10/2026
MM/DD/YYYY	10/12/2026
YYYY-MM-DD	2026-10-12
Default por país:

Venezuela, España, Francia: DD/MM/YYYY.

USA: MM/DD/YYYY.

Brasil: DD/MM/YYYY.

💰 Formato de moneda
Se usa el locale del usuario para el formato (Intl.NumberFormat).

El símbolo de moneda según ISO-4217.

Ejemplos:

es-VE, Bs: Bs 1.234,56

en-US, USD: $1,234.56

pt-BR, BRL: R$ 1.234,56

### 🔢 Formato de números
Separador decimal: según locale.
Separador de miles: según locale.
Nunca mostrar números crudos sin formato.

### 🌍 Multimoneda en UI
Todo monto muestra su moneda.
Si hay conversión, se muestra el tipo de cambio aplicado.
Ejemplo:
Bs 40.000,00
(equivalente a $1.000,00 USD @ 40,00)

### 📄 PDFs internacionalizados
Recibos, contratos, actas, reportes:
Idioma del usuario que solicita.
Timezone del condominio.
Formato de fecha del condominio.
Moneda del condominio.

### 🔔 Notificaciones internacionalizadas
Idioma del destinatario.
Timezone del destinatario.
Plantillas en notification_templates por locale.

### 🧪 Testing i18n
Test que verifica que todas las claves existen en los 4 locales.
Test que verifica que no hay claves huérfanas.
Test que renderiza páginas en cada locale.

Comando:
pnpm i18n:check
Falla el CI si hay claves faltantes.

## 🚨 Reglas duras
1. Nunca hardcodear strings visibles al usuario.
2. Nunca concatenar strings traducibles.
3. Siempre agregar claves en los 4 idiomas.
4. Siempre guardar fechas en UTC.
5. Siempre renderizar en timezone del condominio o del usuario.
6. Nunca usar new Date() sin timezone explícita.
7. Nunca asumir formato de fecha/número.
8. Siempre usar las utilidades compartidas de packages/i18n.

🧰 Utilidades compartidas
ts
// packages/i18n/format.ts
export function formatDate(date: Date, timezone: string, format: string): string;
export function formatCurrency(amount: Decimal, currency: string, locale: string): string;
export function formatNumber(value: number, locale: string): string;
export function formatDateTime(date: Date, timezone: string, format: string): string;
Regla: ningún módulo formatea fechas o monedas por su cuenta. Siempre usa estas utilidades.

📌 Checklist de PR (i18n)
□ Ninguna string visible hardcodeada.
□ Todas las claves agregadas en los 4 locales.
□ pnpm i18n:check pasa.
□ Fechas renderizadas con timezone correcta.
□ Monedas renderizadas con locale correcto.
□ PDFs usan locale y timezone correctos.
□ Notificaciones usan idioma del destinatario.

🔒 Fallbacks
Si falta una clave en un locale, se usa en.
Si falta en en, se muestra la clave (visible en dev, log en prod).
El CI bloquea el merge si hay claves faltantes.
